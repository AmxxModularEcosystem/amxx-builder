# RPC-инструменты (опционально)

28 дополнительных MCP-инструментов управляют **живым** AMX Mod X сервером через модуль `amxx-rpc-module` (JSON-RPC 2.0 поверх TCP). Они позволяют выполнять серверные команды, читать и менять cvar, смотреть игроков, подписываться на события, создавать фейк-игроков и управлять ботами YAPB. Базовые инструменты (`.inc`, манифесты, зависимости) описаны в [INDEX.md](../INDEX.md) и работают без сервера.

Инструменты **скрыты по умолчанию**. Они появляются в списке MCP только тогда, когда задан `AMXB_RPC_TOKEN` (и `AMXB_RPC_ENABLED` не равен `0`). Без токена сервер их не регистрирует вообще.

## Включение

Настройки читаются MCP-сервером из `.env` рядом с манифестом (или текущей рабочей директории), как и остальные переменные `AMXB_*`. Минимальный `.env`:

```env
AMXB_RPC_TOKEN=your-shared-secret-at-least-16-chars
```

### Переменные окружения

| Переменная | Обязательность | По умолчанию | Описание |
|------------|:---:|--------------|----------|
| `AMXB_RPC_HOST` | — | `127.0.0.1` | Хост RPC-эндпоинта |
| `AMXB_RPC_PORT` | — | `27016` | TCP-порт модуля. Это **собственный** порт модуля, **отдельный** от игрового/RCon порта `27015` |
| `AMXB_RPC_TOKEN` | ✓ | — | Общий секрет (не короче 16 символов). Должен совпадать с `token` в `addons/amxmodx/configs/amxxrpc.cfg`. Без него инструменты скрыты |
| `AMXB_RPC_TIMEOUT` | — | `15` | Таймаут одного запроса и установки TCP-соединения, в **секундах**. Если хост недоступен (пакеты дропаются, как при WSL → Windows), вызов завершится ошибкой `-32003`, а не зависнет |
| `AMXB_RPC_ENABLED` | — | — | Явный тумблер: `1/true/yes/on` включает, `0/false/no/off` **принудительно скрывает** инструменты даже при заданном токене |

`AMXB_RPC_TOKEN` и `AMXB_RPC_ENABLED` имеют приоритет: если включение не подтверждено токеном или включение выключено явно, RPC-инструменты не регистрируются.

## Подключение, переподключение и ошибки

Первое сообщение на каждом соединении — автоматический `rpc.auth` с токеном. При неверном токене сервер отвечает ошибкой `-32001` и закрывает соединение.

Клиент подключается лениво: соединение открывается при первом вызове инструмента. Если оно оборвалось, следующий вызов переподключается сам, а подписки на события (`events_subscribe`) восстанавливаются автоматически после переподключения.

Инструменты возвращают RPC-поле `result` как отформатированный JSON. Ошибки RPC пробрасываются в модель как есть:

| Код | Значение |
|-----|----------|
| `-32700` | Ошибка разбора JSON |
| `-32600` | Некорректный запрос |
| `-32601` | Метод не найден |
| `-32602` | Некорректные параметры |
| `-32603` | Внутренняя ошибка |
| `-32001` | Не аутентифицирован (неверный или отсутствующий токен) |
| `-32002` | Сервис недоступен (например, не установлен YAPB) |
| `-32003` | Ошибка движка/AMXX |
| `-32004` | Сервер занят |
| `-32005` | Таймаут запроса |

`rpc_call` — запасной путь: через него можно вызвать любой метод, зарегистрированный Pawn-плагинами через include `AmxxRpc`, а также методы, которые появятся в будущем. Набор доступных методов возвращает `rpc_methods`.

## WSL и сетевое взаимодействие

По умолчанию модуль слушает `host = 127.0.0.1`, поэтому процесс WSL/opencode в другом сетевом пространстве **не сможет** до него достучаться. Чтобы использовать RPC из WSL:

1. В `addons/amxmodx/configs/amxxrpc.cfg` задайте `host = 0.0.0.0` (или LAN-IP Windows-машины).
2. Разрешите порт в брандмауэре Windows.
3. Укажите в `AMXB_RPC_HOST` IP-адрес Windows-хоста, доступный из WSL: например, IP шлюза по умолчанию (`ip route | grep default`) или nameserver из `/etc/resolv.conf`. При mirrored networking WSL может работать и `localhost`.

`localhost` из WSL в сторону Windows часто **не** работает: нужен именно host-IP. Токен передаётся в открытом виде (без TLS), поэтому держите соединение на loopback или в доверенной сети.

## Безопасность

`server_exec` и `cvar_set` (а также, в меньшей степени, манипуляции фейк-игроками и ботами) напрямую влияют на живой сервер. Токен — это секрет с полным доступом. Инструменты скрыты, пока не настроены, и их **не следует** включать в недоверенной сети.

## Каталог инструментов

### Общие

#### `rpc_call`

Вызывает произвольный RPC-метод и возвращает сырой `result`. Запасной путь для методов Pawn-плагинов (`AmxxRpc`) и будущих методов; список доступного даёт `rpc_methods`.

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `method` | `string` | ✓ | Имя RPC-метода |
| `params` | `object` | — | Параметры метода. По умолчанию `{}` |

#### `rpc_methods`

Возвращает каталог методов, зарегистрированных на сервере (включая методы Pawn-плагинов).

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `grep` | `string` | — | Фильтр по подстроке имени метода (без учёта регистра) |

#### `rpc_status`

Возвращает версию и пинг модуля: результат `rpc.version` + `rpc.ping`. Параметров нет.

### Ядро сервера

#### `server_exec`

Выполняет консольную команду сервера. Вывод команды **не** захватывается.

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `command` | `string` | ✓ | Консольная команда |

#### `cvar_get`

Читает значение cvar.

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `name` | `string` | ✓ | Имя cvar |

#### `cvar_set`

Устанавливает значение cvar.

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `name` | `string` | ✓ | Имя cvar |
| `value` | `string` | ✓ | Новое значение |

#### `players_list`

Возвращает массив игроков в формате `{index,name,authid,team,health,origin}`. Параметров нет.

#### `player_get`

Возвращает данные одного игрока.

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `index` | `number` | ✓ | Индекс игрока |

### События

#### `events_subscribe`

Подписывает клиента на серверное событие. После переподключения подписки восстанавливаются автоматически.

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `event` | `string` | ✓ | Имя события |

#### `events_unsubscribe`

Отписывает клиента от серверного события.

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `event` | `string` | ✓ | Имя события |

#### `events_drain`

Возвращает буферизованные уведомления сервер → клиент, накопленные с прошлого вызова.

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `limit` | `number` | — | Максимум уведомлений за вызов |
| `clear` | `boolean` | — | Очистить буфер после чтения |

**Параметры**

#### `fake_look`

Задаёт направление взгляда фейк-игрока: либо углами, либо точкой. Нужен хотя бы один из `angles` / `at`.

**Параметры**

| `angles` | `number[]` | — | Углы `[pitch, yaw, roll]` |
| `at` | `number[]` | — | Точка `[x, y, z]`, куда смотреть |

#### `fake_stop`

Останавливает движение фейк-игрока.

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `index` | `number` | ✓ | Индекс фейк-игрока |

### Боты (нужен YAPB)

Эти инструменты требуют установленного YAPB. Если его нет, `bot_available` возвращает `{available:false}`, а остальные вызовы падают с ошибкой `-32002`.

#### `bot_available`

Проверяет, доступны ли боты YAPB. Параметров нет.

#### `bot_add`

Добавляет бота.

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `name` | `string` | ✓ | Имя бота |
| `difficulty` | `number` | — | Сложность |
| `personality` | `string` | — | Характер |
| `team` | `number` | — | Номер команды |

#### `bot_list`

Возвращает список ботов. Параметров нет.

#### `bot_goal`

Задаёт цель бота.

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `index` | `number` | ✓ | Индекс бота |
| `origin` | `number[]` | — | Точка `[x, y, z]` |
| `node` | `number` | — | Номер узла навигации |

#### `bot_look`

Заставляет бота смотреть в точку.

**Параметры**

| Поле | Тип | Обязательный | Описание |
|------|-----|:---:|---------|
| `index` | `number` | ✓ | Индекс бота |
| `origin` | `number[]` | ✓ | Точка `[x, y, z]` |

#### `bot_freeze`

Заморозить или разморозить бота.

**Параметры**

#### `bot_status`

**Параметры**

## Примеры

```
— Покажи игроков на сервере
— Выполни `amx_map de_dust2`
— Поставь cvar sv_cheats 1
— Что сейчас со здоровьем у игрока 3?
— Подпишись на событие player_death и выведи буферизованные события
— Создай фейк-игрока Bot1 с авторидом STEAM_1:0:1
— Заставь бота 2 смотреть на точку 100 200 300
— Доступны ли боты YAPB на этом сервере?
— Вызови RPC-метод myplugin.action через rpc_call
— Проверь версию RPC-модуля и пинг
```
